4. STEP-BY-STEP INSTALLATION
================================================================================

STEP 1: Install Prerequisites

  Open a terminal and verify:

      node --version       Should be v18 or higher
      npm --version        Should be v9 or higher
      mongod --version     Should be v6 or higher

  If MongoDB is not installed:

    Windows:
      1. Download installer from https://www.mongodb.com/try/download/community
      2. Run installer (select "Complete" setup)
      3. MongoDB runs as a Windows service automatically

    macOS:
      brew tap mongodb/brew
      brew install mongodb-community
      brew services start mongodb-community

    Linux (Ubuntu/Debian):
      curl -fsSL https://www.mongodb.org/static/pgp/server-7.0.asc | sudo gpg --dearmor -o /usr/share/keyrings/mongodb-server-7.0.gpg
      echo "deb [ signed-by=/usr/share/keyrings/mongodb-server-7.0.gpg ] https://repo.mongodb.org/apt/ubuntu jammy/mongodb-org/7.0 multiverse" | sudo tee /etc/apt/sources.list.d/mongodb-org-7.0.list
      sudo apt update
      sudo apt install -y mongodb-org
      sudo systemctl start mongod
      sudo systemctl enable mongod

STEP 2: Clone the Repository

      git clone <repository-url>
      cd Inventory/project1/enterprise

STEP 3: Backend Setup

      cd backend
      npm install

      The .env file comes pre-configured for local development.
      Default backend/.env contents:

        PORT=5000
        MONGODB_URI=mongodb+srv://<db_user>:<db_pass>@skrt.c8bhau6.mongodb.net/skrt_transport?appName=SKRT
        JWT_SECRET=<change-this-in-production>
        CLOUDINARY_CLOUD_NAME=dv7tcudnv
        CLOUDINARY_API_KEY=<your-cloudinary-api-key>
        CLOUDINARY_API_SECRET=<your-cloudinary-api-secret>
        NODE_ENV=development
        FRONTEND_URL=http://localhost:3001

      NOTE: Change JWT_SECRET and Cloudinary credentials for production.

STEP 4: Seed the Database

      node seed-admin.js

      This creates:
        - Admin user:  admin@skrt.com / Admin@1234
        - Manager user: manager@skrt.com / Manager@1234

      For full demo data (sample shipments, vehicles, invoices, etc.):
        node seed.js

STEP 5: Frontend Setup

      cd frontend
      npm install

      Default frontend/.env.local contents:

        NEXT_PUBLIC_API_URL=http://localhost:5000/api
        NEXT_PUBLIC_MAPBOX_TOKEN=<your-mapbox-token>

      NOTE: Mapbox token is only needed for the tracking map page. Leave blank if not using.

STEP 6: Verify MongoDB Connection

      cd backend
      node check_db.js

      Expected output: Connected successfully to MongoDB

5. CONFIGURATION
================================================================================

BACKEND CONFIGURATION (backend/.env):

  Variable                    Required  Description
  --------                    --------  -----------
  PORT                        No        Backend server port (default: 5000)
  MONGODB_URI                 Yes       MongoDB connection string
  JWT_SECRET                  Yes       Secret key for JWT token signing (min 32 chars)
  JWT_EXPIRE                  No        Token expiry (default: 30d)
  CLOUDINARY_CLOUD_NAME       Yes       Cloudinary cloud name (file uploads)
  CLOUDINARY_API_KEY          Yes       Cloudinary API key
  CLOUDINARY_API_SECRET       Yes       Cloudinary API secret
  NODE_ENV                    Yes       "development" or "production"
  FRONTEND_URL                Yes       Frontend URL for CORS

FRONTEND CONFIGURATION (frontend/.env.local):

  Variable                    Required  Description
  --------                    --------  -----------
  NEXT_PUBLIC_API_URL         Yes       Backend API base URL (include /api suffix)
  NEXT_PUBLIC_MAPBOX_TOKEN    No        Mapbox token for tracking maps (optional)

CORS Configuration:
  The backend allows requests from:
    - http://localhost:3001
    - The value of FRONTEND_URL in .env
  Add additional origins in backend/src/app.js if needed.

      cd frontend

      cd frontend
      npm run lint

ADDING A NEW BACKEND MODULE:

  Each module follows this pattern:

      src/modules/<name>/
      ├── model.js       Mongoose schema + model
      ├── controller.js  Request handlers
      └── routes.js      Express router

  1. Create the module directory with model, controller, routes files
  2. Register routes in backend/src/app.js:
       app.use('/api/<name>', require('./modules/<name>/routes'));

10. TROUBLESHOOTING
================================================================================

PROBLEM: "MongoDB Connection Error: connect ECONNREFUSED"
  Cause: MongoDB is not running.
  Fix:
    Windows: net start MongoDB
    macOS:   brew services start mongodb-community
    Linux:   sudo systemctl start mongod

PROBLEM: "Not allowed by CORS"
  Cause: Frontend URL not whitelisted.
  Fix: Add URL to allowedOrigins in backend/src/app.js or update FRONTEND_URL.

PROBLEM: "Missing credentials" / 401 on API calls
  Cause: JWT token missing or expired.
  Fix: Log out and log in again. Check localStorage for "token" key.

PROBLEM: "Cannot find module '...'"
  Cause: Dependencies not installed.
  Fix:
    cd backend && npm install
    cd frontend && npm install

PROBLEM: Port already in use
  Cause: Another process using port 5000 or 3001.
  Fix: Change port in .env (backend) or package.json dev script -p flag (frontend).

PROBLEM: "MongooseError: Operation '...' buffering timed out"
  Cause: MongoDB connection lost or never established.
  Fix: Check MongoDB is running and MONGODB_URI is correct. Restart both.

PROBLEM: Frontend shows blank page / white screen
  Fix:
    1. Check browser console for errors
    2. Verify NEXT_PUBLIC_API_URL is correct
    3. Clear browser cache and localStorage
    4. Run npm run build

11. DEPLOYMENT
================================================================================

DEPLOY TO VERCEL:

  Both backend and frontend have vercel.json configurations.

  Backend:
      cd backend
      npx vercel --prod

  Frontend:
      cd frontend
      npx vercel --prod

  Set environment variables in Vercel dashboard for each project.

PRODUCTION CHECKLIST:

  1. Change JWT_SECRET to a strong random value
  2. Set NODE_ENV=production in backend
  3. Use MongoDB Atlas for managed database
  4. Enable HTTPS (Vercel provides this by default)
  5. Set up proper CORS origins for your production domain only
  6. Remove or secure development keys (Cloudinary, Mapbox)
  7. Set up MongoDB backups (Atlas provides automated backups)
  8. Use PM2 process manager if not using Vercel:
       npm install -g pm2
       pm2 start src/server.js --name skrt-backend
       pm2 save
       pm2 startup

PRODUCTION ENVIRONMENT VARIABLES:

  Backend (Vercel):
      PORT=5000
      MONGODB_URI=mongodb+srv://<db_user>:<db_pass>@skrt.c8bhau6.mongodb.net/skrt_transport?appName=SKRT
      JWT_SECRET=<long-random-string>
      JWT_EXPIRE=30d
      NODE_ENV=production
      FRONTEND_URL=https://your-frontend-domain.vercel.app
      CLOUDINARY_CLOUD_NAME=dv7tcudnv
      CLOUDINARY_API_KEY=<your-cloudinary-api-key>
      CLOUDINARY_API_SECRET=<your-cloudinary-api-secret>

12. ARCHITECTURE OVERVIEW
================================================================================

DATA FLOW:

    Browser (Next.js)
        |
        +-- Axios --HTTP--> Express API --Mongoose--> MongoDB
        |                     |
        +-- Socket.io Client -WebSocket-> Socket.io Server
                                          |
                                          +-- Real-time tracking updates

AUTHENTICATION FLOW:

    1. User submits credentials --> POST /api/auth/login
    2. Backend validates --> returns JWT token
    3. Frontend stores token in localStorage
    4. Every request includes Authorization: Bearer <token>
    5. Auth middleware verifies token on protected routes
    6. Token expiry --> 401 --> redirect to login

KEY DESIGN DECISIONS:

  - Page-based architecture: Each major feature (Shipments, Inventory,
    Invoices, etc.) has its own page under src/app/ and its own backend
    module under src/modules/

  - Global Search: Header search queries /api/search endpoint that searches
    across all observation collections in parallel (Shipments, Invoices,
    Vehicles, Clients, Inventory, Tracking)

  - Real-time tracking: Socket.io broadcasts location updates. Frontend
    listens on specific shipment channels for live map updates

  - Data-entry forms (Entry, Summary, DS, Challan, Cash Memo) are blank
    daily forms - always POST (never PUT), auto-generate sequence numbers,
    and reset after save

  - Driver data is stored in a dedicated Driver collection with vehicle
    number as key. Vehicle/Driver dropdowns source from this collection,
    with an "Others" option for manual entry of unregistered vehicles/drivers

  - All API routes except login require authentication via JWT middleware

MONGODB COLLECTIONS:

  Collection              Stores                          Key Relationships
  ----------              ------                          ----------------
  users                   Authentication & user roles    -
  shipments               Consignment records             Uses driver's vehicleNumber as string ref
  inventories             Warehouse stock                 Links to challans
  invoices                Billing records                 References shipment ID
  vehicles                Fleet vehicles                  Referenced by tracking
  drivers                 Driver info (name, phone, veh)  Keyed by vehicleNumber
  trackings               Live GPS data                   References vehicle ID
  clients                 Client companies                Used in invoice subdocs
  contacts                Consignor/consignee addresses   Used in shipments
  expenses                Fleet expenses                  References vehicle
  notifications           System alerts                   References user (nullable)
  entryregisters          Daily entry forms               Date-keyed
  summaryregisters        Daily summaries                 Date-keyed
  deliverystatements      Delivery statements             Date + pageNo-keyed
  challans                Transport challans              Date-keyed
  cashmemos               Cash memos                      GR No. / DR No. indexed
  seeddata                Seeding metadata                Internal use
